class MobileInput

package jta.mobile

extends FlxTypedGroup

@:directlyUsed

Handles virtual touchscreen controls.

Layouts are computed from the button size and screen size, so changing buttonSize, utilSize, margin or spacing keeps everything on screen and non-overlapping.

Static variables

staticread onlyactiveInstance:Null<MobileInput>

Currently active mobile input manager (the most recently created one that is still alive). Input.hx uses this to query touchscreen controls.

staticread onlybarHeight:Float

Height of the letterbox bar above and below the game, in game pixels.

staticread onlybarWidth:Float

Width of the letterbox bar on each side of the game, in game pixels.

@:value(96)staticbuttonSize:Float = 96

On-screen size of the main buttons (A/B/arrows), in pixels.

@:value(24)staticmargin:Float = 24

Distance from the top and bottom edges of the screen.

@:value(40)staticsideMargin:Float = 40

Distance from the left and right edges of the screen. A bit larger than margin to keep clear of rounded screen corners and camera cutouts.

@:value(12)staticspacing:Float = 12

Gap between neighbouring buttons.

@:value(64)staticutilSize:Float = 64

On-screen size of utility buttons (pause/back/skip), in pixels.

staticinlinegameToScreenY(y:Float):Float

Converts a y position in game coordinates into controls-camera coordinates.

staticgetControlsCamera():FlxCamera

Returns the camera the touch controls are drawn on, creating it if needed. It's added on top of every other camera and stretched to cover the whole device screen, letterbox bars included.

Flixel removes all cameras when the state switches, so a new one is made for each state; substates (pause menu etc.) reuse their state's.

staticupdateAll():Void

Samples touch input for every live layout. Called by the plugin.

Layout used while a dialogue box is open: A advances, B skips.

Parameters:

The top of the dialogue box, if it sits at the bottom of the screen. The buttons are placed just above it so they don't cover the text.

setupGameplay():Void

Shows the standard gameplay layout.

Left/right in the bottom-left, run (B) and jump (A) in the bottom-right, pause at the top centre (the HUD uses both top corners), and a contextual interact button above the arrows that only appears when the player is standing on something interactable.
